## これは何か

`docs/requests/` に置かれた依頼（Cowork が書いた Markdown）を確認し、着手できるものを実装して、
型チェックとテストが通れば本番（`main`）へ反映するための手順。ワークスペース（`~/Desktop/WEBアプリ用`）の常駐から
`claude -p "/cowork-check" --permission-mode acceptEdits` としてヘッドレス起動される想定。
このアプリ専用のスクリプトは持たず、`../scripts/` にあるワークスペース共通のものを使う。

このプロジェクトの本番反映ルールは `CLAUDE.md` に書かれている。矛盾する場合は `CLAUDE.md` が優先。

## 手順

### 0. 手元を最新にしてから始める

```
git fetch
git status --porcelain --untracked-files=no
git rev-list --count HEAD..@{u}
```

- 作業途中の変更なし → `git pull --rebase` で最新にしてから 1 へ進む。
- 作業途中はあるが遅れてはいない（`git rev-list ...` が `0`）→ そのまま 1 へ進む。
- 遅れがある（1以上）→ **実装しない。** `../.cowork/apps/AI議事録ツール/waiting.txt` に理由を追記して報告して終わる。
- `git rev-list` がエラー（＝リモート未設定）→ 同期は不要。そのまま 1 へ進む。

**`git stash` / `git checkout` / `git reset` で人の作業を退かしてはいけない。** 待つか、進むかの二択。

### 1. 状況を確認する

```
bash ../scripts/cowork-watch.sh --app "AI議事録ツール"
```

`../.cowork/apps/AI議事録ツール/waiting.txt` の中身も必ず読むこと。

**`../.cowork/apps/AI議事録ツール/pending.md` も必ず読む。** `[ ]` が残っていれば、それは
「前回までに取り込んだが、まだ実装が終わっていない」項目。新しい依頼が無くても、これが残っているうちは終わりではない。

### 2. 依頼ごとに、着手できるか判断する

次のいずれかに当てはまる依頼は、実装せず `../.cowork/apps/AI議事録ツール/waiting.txt` に理由を追記して止める（既存の内容は消さず追記）。

- 何をしたいのかが依頼から読み取れない
- 外部サービス（Azure・Netlifyの環境変数設定など）の新規登録・APIキー発行が必要で、まだキーが用意されていない
  （用意ができるまでは、CLAUDE.md の「暫定でブラウザ標準の音声認識を使う」方針で進められる部分は進めてよい）
- 本番データを消す／作り直す性質の変更

文言・色・並び順・細かい UI の詰めなど、依頼に書かれていない細部は自分で妥当な案を採って進めてよい。

### 2.5 実装を始める前に、やることを全部キューへ書き出す

着手すると決めた依頼について、その依頼に含まれる項目を `../.cowork/apps/AI議事録ツール/pending.md` へ**全部**書き出してから、はじめて実装に入る。

```markdown
## <依頼のファイル名>（取り込み: YYYY-MM-DD）
- [ ] 項目1
- [ ] 項目2
```

保留にした項目も `[ ]` のまま残し、理由を1行添える（`../.cowork/apps/AI議事録ツール/waiting.txt` にも書く）。

### 3. 実装する

- 既存のコード規約・パターンに合わせる
- 依頼された範囲を超える変更を勝手に追加しない
- 1つの依頼につき、意味のある単位でコミットする

#### `../scripts/` のスクリプトの呼び方

`cd` もパイプも付けず、**単独で**呼ぶこと。

```
bash ../scripts/cowork-watch.sh --app "AI議事録ツール"     # ○
cd .. && bash scripts/cowork-watch.sh ... | tail -20        # × 承認待ちで止まる
```

同じ理由で、ワークスペース側のリポジトリ（`.cowork/` の状態）を `git -C "<ワークスペース>" add ...` の形で
触るのも通らない。専用のスクリプトを使う。

```
bash ../scripts/cowork-commit-state.sh AI議事録ツール -m "やりかけを更新"
```

書き込みが許されているのは `AI議事録ツール` と `../.cowork/apps/AI議事録ツール` の2か所だけで、
`../scripts/` や `.claude/` にファイルを作ることはできない。そこへ足したいものがある時は、
`docs/cowork/` に置いて README に移し方を書き、保留として報告する。

### 4. 検証する（省略・無効化しない）

```
npx tsc --noEmit
npm test
```

**両方とも通った場合のみ**次に進む。1つでも落ちたら、直せるならその場で直して再実行する。
直せない場合はコミットせず、その依頼は `着手可` のまま残す。

### 5. コミットして反映する

```
git add <変更したファイル>
git commit -m "<内容が分かるメッセージ>"
git push
```

（リモートがまだ無い場合は push は省略し、ローカルへのコミットまでで良い。その旨を報告する。）

その依頼について型チェック・テストが通り、コミットも完了したら、`../.cowork/apps/AI議事録ツール/state.tsv` に記録する。

```
bash ../scripts/cowork-watch.sh --app "AI議事録ツール" --update --done "<依頼のファイル名>.md"
```

**記録してよいのは、その依頼の項目が `../.cowork/apps/AI議事録ツール/pending.md` で全部 `[x]` になったときだけ。**

処理できた依頼がある場合は、`CLAUDE.md` の本番反映ルールに従って `main` へマージし push する
（リモートがある場合のみ。型チェック・テストが通った変更のみ。強制プッシュ・履歴の書き換えはしない）。

### 6. 報告する

- 実装して本番に入れた依頼（何をしたか）
- 実装にあたって自分の判断で決めた細部
- 保留にした依頼とその理由
- やりかけとして `pending.md` に残した項目
- 何も対象がなかった場合はその旨
